第 9 章 · Part 5：1.x 新版與生態系

進階設定與 CLI 速查（1.x 新版）

零設定是預設，需要時再用 codegraph.json 微調；本章把 1.x 新增的指令、設定與供應鏈驗證一次補齊。

本書前八章寫於 0.9.x 版本。1.x 之後，CodeGraph 新增了 codegraph.json 設定檔、 explore／node 等 CLI 指令、affected 測試影響分析、 匿名 Telemetry，以及可驗證的發行流程。本章依官方 README（1.x）整理這些前幾章沒寫到的內容， 並附上筆者在 1.6.2 上的實測結果。

9.1 codegraph.json 設定檔

CodeGraph 預設是 zero-config：語言支援由副檔名自動判斷，不需要為每種語言設定任何東西。 唯一的可選設定檔是專案根目錄的 codegraph.json，用來調整「哪些檔案進索引」與「搜尋時誰排前面」。

預設會跳過什麼

  • 相依、建置與快取目錄：node_modules、vendor、dist、build、target、.venv、Pods、.next 等，涵蓋所有支援的技術堆疊；即使專案沒有 .gitignore 也一樣。
  • .gitignore 內的內容：git 專案透過 git 判斷；非 git 專案則直接讀取 .gitignore（含根目錄與子目錄）。
  • 大於 1 MB 的檔案：例如產生的 bundle、minified JS、第三方二進位大檔。

想排除其他東西，先加進 .gitignore 即可；想把預設排除的目錄拉回索引， 在 .gitignore 加上否定語法：

.gitignore 
# .gitignore：把預設被排除的目錄拉回索引
!vendor/

四個欄位的分工

欄位 用途 何時使用
exclude 從索引中移除，gitignore 風格 pattern，以專案根目錄相對路徑比對；索引、同步、監聽三個階段都生效 已 commit 進 repo 的第三方內容（例如放在 static/ 的佈景主題或 SDK），.gitignore 擋不掉
include 強制納入索引，覆蓋 .gitignore；索引、同步、監聽都生效 原始碼被刻意 gitignore 的專案，例如同時使用 SVN 或 Perforce、為了不進 Git 而把自己的原始碼寫進 .gitignore
deprioritize 路徑仍在索引內、仍可搜尋，只是排名不再壓過主要程式碼；影響 query／search 與 explore 的排序 scripts/、optional-skills/ 這類目錄的輔助函式用了 usage、status、run 之類的泛用名稱，會因名稱完全相符而搶走產品程式碼的名次
extensions 把非標準副檔名對應到支援的語言 id 專案使用自訂副檔名，例如 .dota_lua 對應 Lua、.tpl 對應 PHP；預設這些檔案會被跳過

exclude：擋下已 commit 的目錄

codegraph.json 
{
  "exclude": ["static/", "**/vendor/**"]
}

若明確寫了 exclude，它的優先權高於 include。

include：把被 gitignore 的原始碼拉回來

codegraph.json 
{
  "include": ["Tools/", "Local/typescript/"]
}

CodeGraph 會直接從磁碟找到這些檔案，無視 .gitignore。 但內建的跳過項目（node_modules、dist、.git）不會被 include 重新納入。

deprioritize：降權而非移除

codegraph.json 
{
  "deprioritize": ["optional-skills/", "scripts/"]
}

deprioritize 只改變排名，不是過濾器。官方特別區分：內建的 example/、sample/、fixture/、benchmark/、demo/ 處理會在部分結果集中直接剔除那些檔案，而 deprioritize 永遠只改排名。要讓東西徹底消失，請用 exclude。

extensions：自訂副檔名

codegraph.json 
{
  "extensions": {
    ".dota_lua": "lua",
    ".tpl": "php"
  }
}

每個值必須是支援的語言 id。對應表會疊加在內建預設之上，衝突時以你的設定為準， 所以也可以重新指定內建副檔名（例如把 .h 指向 cpp）。 語言名稱打錯或檔案格式錯誤時只會顯示警告並略過，不會讓索引失敗；沒有 codegraph.json 的專案行為與以前完全相同。 新增或修改對應後，要重新索引：

bash 
# 新增或修改 codegraph.json 之後，重新索引
codegraph index
💡
codegraph.json 建議提交進版本控制

官方建議把 codegraph.json 一併 commit，讓團隊共用同一份副檔名對應。 注意這與前面章節提到的 .codegraph/ 資料庫目錄不同：資料庫是衍生產物，設定檔則是專案約定。

9.2 CLI 速查（1.x 全部指令）

以下是官方 README「CLI Reference」的完整指令清單，與原文逐字一致：

CLI Reference 
codegraph                         # Run interactive installer
codegraph install                 # Run installer (explicit)
codegraph uninstall               # Remove CodeGraph from your agents AND the CLI (--keep-cli for configs only)
codegraph init [path]             # Initialize a project + build its graph (one step)
codegraph uninit [path]           # Remove CodeGraph from a project (--force to skip prompt)
codegraph index [path]            # Full index (--force to re-index, --quiet for less output)
codegraph sync [path]             # Incremental update
codegraph status [path]           # Show statistics
codegraph unlock [path]           # Remove a stale lock file that's blocking indexing
codegraph query <search>          # Search symbols (--kind, --limit, --json)
codegraph explore <query>         # Relevant symbols' source + call paths in one shot (same output as the codegraph_explore MCP tool)
codegraph node <symbol|file>      # One symbol's source + callers, or read a file with line numbers (same output as codegraph_node)
codegraph files [path]            # Show file structure (--format, --filter, --max-depth, --json)
codegraph callers <symbol>        # Find what calls a function/method (--limit, --json)
codegraph callees <symbol>        # Find what a function/method calls (--limit, --json)
codegraph impact <symbol>         # Analyze what code is affected by changing a symbol (--depth, --json)
codegraph affected [files...]     # Find test files affected by changes (see below)
codegraph daemon                  # Manage background daemons — pick one to stop (alias: daemons)
codegraph telemetry [on|off]      # Show or change anonymous usage telemetry
codegraph upgrade [version]       # Update to the latest release (--check, --force)
codegraph version                 # Print the installed version (also -v, --version)
codegraph help [command]          # Show help, optionally for one command
分類 指令 用途
安裝與移除 install／uninstall 把 CodeGraph 接到各 agent 或從中移除；直接執行 codegraph 會進入互動式安裝程式
專案生命週期 init／uninit／index／sync／status／unlock 初始化並建圖、移除專案索引、全量索引、增量更新、顯示統計、移除卡住索引的殘留 lock 檔
查詢與分析 query／explore／node／files／callers／callees／impact／affected 搜尋符號、一次取回相關原始碼與呼叫路徑、讀取單一符號或檔案、檢視檔案結構、找呼叫者與被呼叫者、影響範圍分析、找受影響測試
維運 daemon／telemetry／upgrade／version／help 管理背景 daemon、開關匿名統計、升級、顯示版本、說明

1.x 新增的重點指令

  • codegraph explore <query>：一次取回相關符號的原始碼與呼叫路徑， 輸出與 MCP 工具 codegraph_explore 相同。子代理（subagent）與不支援 MCP 的環境看不到 MCP 的使用指引， 因此安裝程式會在 agent 的指令檔寫入一小段標記區塊，指向這個 CLI 對應指令。
  • codegraph node <symbol|file>：顯示單一符號的原始碼與呼叫者， 或以附行號的方式讀取一個檔案；輸出與 codegraph_node 相同。
  • codegraph daemon：管理背景 daemon，用來挑選要停止的那一個（別名 daemons）。 官方說明 CodeGraph 對每個專案只允許一個即時的 MCP 寫入者（共用的背景 daemon，或單一直接模式程序）， 多個 MCP 客戶端應共用同一個 daemon。
  • codegraph telemetry [on|off]：顯示或變更匿名使用統計，詳見 9.5。
  • codegraph upgrade [version]：升級到最新版（可用 --check、--force）。

install 的非互動參數

腳本或 CI 環境可以用旗標跳過所有提示：

bash 
codegraph install --yes                              # auto-detect agents, install global
codegraph install --yes --init                       # same, then build the current project's index (one-shot bootstrap)
codegraph install --target=cursor,claude --yes       # explicit target list
codegraph install --target=auto --location=local     # detected agents, project-local
codegraph install --print-config codex               # print snippet, no file writes
旗標 值 預設
--target auto、all、none，或逗號分隔清單（claude,cursor,...） 互動詢問
--location global、local 互動詢問
--yes 布林；跳過每一步提示 每一步都詢問
--init 布林；接好 agent 後，在目前目錄執行 codegraph init 不執行
--print-config <id> 印出單一 agent 的設定片段後結束，不寫入任何檔案 無
--refresh 只重寫「先前已經設定過」的 agent，不會新增新的 agent（1.6.2 的 install --help 實測；codegraph upgrade 會自動執行） 無

要記得：安裝程式只接線 agent，不會替你索引程式碼。 一次全域 codegraph install 涵蓋所有專案，但每個專案仍需各自執行一次 codegraph init。

⚠️
Windows 升級陷阱：有 MCP 程序執行中，npm 會無聲失敗

實測於 2026-10-10，codegraph 1.6.2：在 Windows 上以 npm i -g @colbymchenry/codegraph@1.6.2 升級時， 若有 codegraph serve --mcp 程序正在執行（例如其他 Claude Code 或 Cursor 視窗）， npm 會因為檔案被佔用而無法覆蓋，而且不會報錯：npm ls -g 顯示 1.6.2， 但 codegraph --version 仍是 0.9.6。升級前請先結束這些程序，升級後以 codegraph --version 驗證。

升級流程 
# 升級前：先確認並結束所有執行中的 codegraph serve --mcp 程序
# 升級後：務必用 --version 驗證實際生效的版本，不要只看 npm ls -g
npm i -g @colbymchenry/codegraph@1.6.2
codegraph --version

9.3 codegraph affected：用相依性找出該跑的測試

codegraph affected 會沿著 import 相依關係做遞移追蹤，找出哪些測試檔受到「被修改的原始檔」影響。 你把改動的檔案交給它，它回報需要重跑的測試，不必每次跑完整測試套件。

bash 
codegraph affected src/utils.ts src/api.ts         # Pass files as arguments
git diff --name-only | codegraph affected --stdin   # Pipe from git diff
codegraph affected src/auth.ts --filter "e2e/*"     # Custom test file pattern
選項 說明 預設
--stdin 從標準輸入讀取檔案清單 false
-d, --depth <n> 相依性追蹤的最大深度 5
-f, --filter <glob> 自訂用來辨識測試檔的 glob 自動偵測
-j, --json 以 JSON 輸出 false
-q, --quiet 只輸出檔案路徑 false

實測：Python 專案

實測於 2026-10-10，codegraph 1.6.2。測試專案是一個小型 Python 專案，包含 scripts/scaffold.py、scripts/gen_copy.py、tests/test_scaffold.py。 對 scripts/scaffold.py 執行 affected 的輸出如下：

實測輸出（1.6.2） 
$ codegraph affected scripts/scaffold.py
Affected test files (1):

  tests/test_scaffold.py

同一份程式碼用 0.9.6 執行，得到的是 No test files affected by the changed files.（找不到）； 1.6.2 則能正確找到對應測試。圖譜本身也有變化：codegraph init -i 在 1.6.2 對該專案建出 6 個檔案、138 個節點、329 條邊，耗時 2.4 秒；0.9.6 的邊數為 297 條。 邊越完整，import 追蹤越不容易漏。

CI 與 git hook

搭配 --stdin 與 --quiet，可以把「本次 diff」直接轉成「要跑的測試清單」：

CI／hook 範例 
#!/usr/bin/env bash
AFFECTED=$(git diff --name-only HEAD | codegraph affected --stdin --quiet)
if [ -n "$AFFECTED" ]; then
  npx vitest run $AFFECTED
fi

git diff --name-only | codegraph affected --stdin --quiet 是這個用法的核心： --quiet 只輸出路徑，方便直接餵給測試執行器。 範例以 vitest 為例，換成你專案的測試指令即可。

ℹ️
affected 的邊界

它依賴靜態 import 相依性。動態派發、反射或 DI 容器造成的關聯，屬於靜態分析的已知邊界（官方在覆蓋率說明中也這樣描述）， 重要變更仍建議在合併前跑完整測試。

9.4 MCP 預設只露出 codegraph_explore

0.9.x 時代的 CodeGraph 提供一整排 MCP 工具。1.x 的 MCP server 預設只列出一個工具： codegraph_explore。官方的理由來自實測的 agent 行為： 一個強工具比一堆窄工具更能引導 agent，選錯工具的情況更少，而且每個 session 都省下 context。

工具 預設是否列出 說明
codegraph_explore 是 一次呼叫回答幾乎任何問題：「X 如何運作」、流程（「X 如何到達 Y」）或某區域的概覽；回傳相關符號的原始碼（依檔案分組）、符號間的呼叫路徑與 blast-radius 摘要，也能呈現 grep 追不到的動態派發跳轉
codegraph_node、codegraph_search、codegraph_callers、codegraph_callees、codegraph_impact、codegraph_files、codegraph_status 否（unlisted） 功能完整保留，但預設不列出；它們回傳的內容在 codegraph_explore 已經內嵌

若想把某些工具重新開放給 MCP，用環境變數 CODEGRAPH_MCP_TOOLS 指定； 或直接使用對應的 CLI 指令（codegraph node／query／callers／callees／impact／files／status）：

bash 
# 重新開放其他 MCP 工具（預設只列出 codegraph_explore）
CODEGRAPH_MCP_TOOLS=explore,node,search,callers

用 projectPath 跨專案查詢

即使 MCP server 自己的根目錄沒有 .codegraph/ 索引，工具仍然可用： 傳入 projectPath 就能查詢任何已建索引的專案，例如 monorepo 裡只有部分服務建了索引，或同一個 session 內要看第二個 repo。 若該路徑沒有索引，會回傳清楚的指引，要求改用內建工具，不會出現刺耳的錯誤；是否要建立索引，仍由你決定。

9.5 Telemetry 與隱私

CodeGraph 會收集匿名使用統計：哪些工具與指令被使用、哪些語言被索引，用來決定語言與 agent 支援的投入方向。

項目 官方說明
會收集 使用了哪些工具與指令、哪些語言被索引
絕不收集 程式碼、路徑、檔名、符號名稱、查詢內容、IP 位址
傳送方式 先在本機彙整成每日總計才會傳送；接收端點的程式碼公開在官方 repo，並依文件列出的欄位清單過濾
詢問時機 安裝程式會在一開始就詢問

隨時可以關閉，三種方式擇一：

bash 
codegraph telemetry off    # or: CODEGRAPH_TELEMETRY=0, or DO_NOT_TRACK=1

官方 repo 的 TELEMETRY.md 列出每一個欄位、關閉方式與完整的資料處理說明。

💡
公司專案的中性建議

依官方說明，Telemetry 不含程式碼與檔案資訊，風險看起來有限。 但在公司內部專案使用前，仍建議先對照 TELEMETRY.md 的欄位清單，並依公司資安政策確認， 再決定是否關閉。若要統一關閉，在部署腳本設定 CODEGRAPH_TELEMETRY=0 或 DO_NOT_TRACK=1 最容易管理。

9.6 發行版驗證

每一個發行檔案都由公開的 Release workflow 建置與發布，而不是從開發者的筆電送出，並附有密碼學證明：

  • npm 套件：透過 npm trusted publishing 發布（OIDC，沒有可能被竊取的長期 npm token）， 並帶有 provenance 證明，把每個版本連結到建置它的確切 commit 與 workflow run。驗證已安裝的內容：
bash 
npm audit signatures
  • GitHub Release 套件（含 SHA256SUMS）帶有已簽署的 build attestation（SLSA v1.0 Build Level 2）。驗證任何下載的套件：
bash 
gh attestation verify codegraph-darwin-arm64.tar.gz -R colbymchenry/codegraph
⚠️
2026 年 7 月前的版本沒有證明

2026 年 7 月之前發布的版本早於這條發行流程，不帶 attestation。 因此若你仍停留在 0.9.x，npm audit signatures 與 gh attestation verify 無法替它們提供同等保證，這也是升級到 1.x 的理由之一。

9.7 支援平台

每個版本都提供自帶 Node runtime 的獨立建置（不需要自行編譯），涵蓋三大桌面作業系統， 同時支援 Intel／AMD（x64）與 ARM（arm64）：

平台 架構 安裝方式
Windows x64、arm64 PowerShell 安裝程式或 npm
macOS x64、arm64 shell 安裝程式或 npm
Linux x64、arm64 shell 安裝程式或 npm

CLI 與 MCP server 跑在自帶的 runtime 上，與你本機的 Node 版本無關。 只有把 CodeGraph 當函式庫嵌入自己的程式時，才會用到你自己的 runtime，並需要 Node 22.5 以上（為了內建的 node:sqlite）。

9.8 本章重點回顧

  • codegraph.json 是唯一的可選設定檔：exclude 移除、include 強制納入、deprioritize 只降權、extensions 對應自訂副檔名。
  • 1.x 新增 explore、node、daemon、telemetry 等指令；install 支援 --target、--location、--yes、--init、--print-config。
  • codegraph affected 以 import 相依性找出受影響測試，搭配 --stdin --quiet 可直接放進 CI 或 git hook。
  • MCP 預設只列出 codegraph_explore；其他工具仍可用，可用 CODEGRAPH_MCP_TOOLS 重新開放，或以 projectPath 查其他專案。
  • Telemetry 為匿名統計且可關閉；發行版以 trusted publishing 與 SLSA attestation 驗證，2026 年 7 月前的版本不適用。
  • Windows 升級前務必先結束 codegraph serve --mcp 程序，升級後用 codegraph --version 驗證。
