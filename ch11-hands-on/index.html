第 11 章 · Part 5：1.x 新版與生態系

實測：用 CodeGraph 分析自己的專案

不引用官方數字，自己跑一遍：同一個專案、兩個版本、每個指令都附真實輸出。

11.1 實驗設計

前面幾章的數據大多來自官方的 benchmark。這一章反過來：拿一個自己手上的小型專案， 用同一份程式碼，分別在 0.9.6（本書最初撰寫時的版本）與 1.6.2（2026-10 的最新版）上實際操作， 看看指令的輸出長什麼樣子、兩個版本差在哪裡。實測日期為 2026-10-10。

實測專案（Python，6 個檔案） 
scripts/
  scaffold.py        # 產生整本書的骨架
  gen_copy.py        # 呼叫 AI 產生首頁與前言文案
  wc_engines.py      # 呼叫免費模型的共用層
  wc_summarize.py    # 素材摘要
  wc_finish_chapter.py
tests/
  test_scaffold.py   # 2 個測試
ℹ️
這一章的數字不是效能 benchmark

專案只有 6 個檔案、138 個節點，每個指令只跑一次，目的是展示「輸出長什麼樣、版本之間有什麼差異」， 而不是量測速度或 Token 節省。要看規模化的數字，請回到第 4 章。

💡
1.6.2 的結果已在全域安裝後重跑一次

本章一開始用 npx 指定版本跑出 1.6.2 的輸出；之後把全域的 codegraph 也升級成 1.6.2， 在乾淨的副本上重新 init -i，status（138 節點、329 邊）、callers warn（5 個）、 impact sanitize_copy --depth 3（9 個符號）、affected（找到 tests/test_scaffold.py） 和 explore 的 Blast radius 都與下面的輸出相同。

11.2 建立索引

bash

# 1.6.2（先用 npx 試跑，之後全域升級成 1.6.2 再跑一次，結果相同）

11.3 explore：一次呼叫看懂一個區域

1.x 把 MCP 預設工具收斂成 codegraph_explore（第 8 章），所以它是最值得實際看輸出的指令。 在 0.9.6 上，一個查詢（4 個符號名稱加一個檔名）回傳了符號之間的呼叫關係，加上這些檔案「逐字、即時」的原始碼：

11.5 affected：這次改動該跑哪些測試

同一份程式碼，兩個版本 
# 同一份程式碼、同一個指令
codegraph affected scripts/scaffold.py

# 0.9.6
[i] No test files affected by the changed files.

# 1.6.2
Affected test files (1):

  tests/test_scaffold.py
⚠️
升級會改變 affected 的結果

0.9.6 對 scripts/scaffold.py 回報「沒有受影響的測試」；1.6.2 才找出 tests/test_scaffold.py。如果你的 CI 用 affected 決定要跑哪些測試， 舊版可能一直在漏跑測試卻沒有任何錯誤訊息。升級後請用一份已知的改動對照一次。

11.6 實測踩到的坑

1. MCP 回報「No CodeGraph project is loaded」

在不是專案根目錄的地方啟動 Agent（這次實測的工作目錄就是這種情況），MCP 伺服器找不到 .codegraph/， 所有工具都會回這個錯誤。索引本身沒有壞，是工作目錄偵測的問題：

實際錯誤訊息 
Error: Tool execution failed: No CodeGraph project is loaded for this session.
Searched for a .codegraph/ directory starting from: C:\path\to\your\workspace
The index is likely fine — this is a working-directory detection issue: the MCP client
launched the server outside your project and didn't report the workspace root. Fix it either way:
  • Pass projectPath to the tool call, e.g. projectPath: "/absolute/path/to/your/project"
  • Or add --path to the server's MCP config args: ["serve", "--mcp", "--path", "/absolute/path/to/your/project"]

兩種解法：在每次呼叫工具時帶 projectPath，或是在 MCP 設定裡固定 --path：

MCP 設定（固定專案路徑） 
{
  "mcpServers": {
    "codegraph": {
      "type": "stdio",
      "command": "codegraph",
      "args": ["serve", "--mcp", "--path", "C:\\path\\to\\your\\project"]
    }
  }
}

2. 同名函式：trace 只挑一個（0.9.6）

專案裡有兩個 main，要求「從 main 追到 sanitize_copy」只會得到其中一條路徑。 改用唯一的名稱當起點即可（第 8 章有完整範例）。

3. Windows 全域升級不報錯卻沒生效

其他視窗的 codegraph serve --mcp 還在執行時，npm i -g 無法覆蓋被佔用的檔案， npm ls -g 顯示新版，codegraph --version 卻還是舊版。 升級後一定要用 --version 核對（第 5 章）。

下一步：把這幾個指令套進你自己的專案，先用 codegraph status 確認索引的語言與節點數， 再用 explore 問一個你真的不確定的架構問題——比起官方的數字，你自己專案上的結果才是最有說服力的證據。
