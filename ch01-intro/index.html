第 1 章 · Part 1：基礎與概念

什麼是 CodeGraph

給 AI Agent 一張精確的「本地代碼地圖」

「在沒有地圖的森林中，每一次尋路都是昂貴的探索。CodeGraph 為 AI Agent 點亮了整個代碼庫的脈絡，讓尋路化為直覺。」

一、 項目快照與起源

CodeGraph（GitHub 倉庫：colbymchenry/codegraph）是由擁有 15 年以上開發經驗的獨立工程師 Colby McHenry 於 2026 年初創建的開源項目。該項目在發佈後迅速獲得開源社群的廣泛關注，曾單日新增數千顆 Star 並登上 GitHub Trending 榜單前列。

它是一套為 Claude Code, Cursor, Antigravity, Gemini CLI, Hermes Agent 等主流 AI 編碼代理程式（Coding Agent）提供前置本地索引的 Model Context Protocol (MCP) 伺服器。

技術棧特點

  • 100% 本地化：沒有 Neo4j、沒有重型的向量資料庫、不調用外部 LLM API。一切計算與儲存均在開發者本地完成。
  • TypeScript 驅動：核心邏輯以 TypeScript 撰寫，高度模組化且易於擴充。
  • 零外部依賴運行：自 0.9.0 版本起，CodeGraph 開始捆綁專屬的 Node 執行期環境（Runtime），支援 Windows / macOS / Linux 平台一鍵免配置運行。

二、 核心架構設計

CodeGraph 的架構理念極其純粹：代碼文件之間的調用、導入、繼承關係屬於確定性結構，沒有必要讓 AI Agent 在每次對話中都用模糊的 grep 重複發現。提前算好並落盤到 SQLite 中，才是最優解。

三、 技術選型決策：Tree-sitter 戰勝 LSP

在「程式如何理解代碼」這一問題上，業界通常存在兩大主流技術門派。CodeGraph 在此做出了非常明確且大膽的工程權衡：

1. 兩大路線的對比

  • LSP 派（Language Server Protocol）：如 rust-analyzer 或 tsserver。真正懂類型系統與泛型，能給出 100% 精確的定義。但缺點是極其沉重、啟動慢，且要求專案必須處於可成功編譯的狀態。
  • Tree-sitter 派（語法樹解析器）：原為 Atom 編輯器的代碼高亮而設計。它只解析語法，不懂跨文件的類型語意。

CodeGraph 最終選擇了 Tree-sitter wasm 路線，放棄了類型推斷的精準度上限，以換取以下三個對 AI Agent 來說致命的優勢：

  1. 語法容錯性強：即使代碼寫到一半、語法有錯或專案暫時無法編譯，Tree-sitter 照樣能解析出抽象語法樹（AST）。
  2. 部署極簡：單一 WASM 檔案即可覆蓋多作業系統平台，無須為每種語言在本地下載配置龐大的編譯鏈與 Language Server。
  3. 增量速度極快：重算受影響子樹的成本僅需毫秒級，能夠完美適應每次存檔（Cmd+S）時的即時索引同步。

💡 補充說明：Tree-sitter 雖然無法 100% 確定 obj.foo() 裡的 obj 究竟是哪個類別的實例，但它知道這是一個「方法調用」，搭配 CodeGraph 的全域名稱匹配與 Import 關係解析，已足以在 95% 的場景下為 AI 提供準確的跳轉導航。

四、 深入探索：Tree-sitter 如何在 CodeGraph 中運作

為了精確理解 Tree-sitter 在 CodeGraph 中的角色，我們需要釐清它是如何將原始代碼字符，最終組裝成圖數據庫（SQLite）中的節點與邊界關係的。

1. 原始碼轉化為抽象語法樹 (AST)

Tree-sitter 的唯一工作是：把原始碼的字串變成一棵結構化的語法樹。

例如以下這段簡單的 Python 程式：

def add(a, b):
    return a + b

經由 Tree-sitter 解析後，會生成如下結構的語法樹 (Concrete Syntax Tree)：

function_definition
├── name: identifier (add)
├── parameters: parameter_list
│   ├── identifier (a)
│   └── identifier (b)
└── body: block
    └── return_statement
        └── binary_expression (+)
            ├── left: identifier (a)
            └── right: identifier (b)

2. Tree-sitter Query (模式匹配) 提取符號

語法樹生成後，CodeGraph 並不會把整棵巨大的 AST 直接塞進資料庫，因為那對 Agent 來說信息量太過冗餘。CodeGraph 會利用 Tree-sitter 提供的高效 S-Expression 查詢語法 (Query Patterns)，只篩選出我們關心的關鍵符號（例如類別、方法、函式定義、路由與引入等）。

例如，若要在原始碼中找出所有的「函式定義」，CodeGraph 會對 Tree-sitter 執行類似以下的查詢式：

(function_definition
  name: (identifier) @function.name
  body: (block) @function.body)

只要命中這個 Pattern，CodeGraph 就會將其包裝為一個 Node 寫入 SQLite。

contains, calls, imports, exports, extends, implements, references, type_of, returns, instantiates 等。
