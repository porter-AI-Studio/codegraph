專案初始化與自動同步機制

一行指令啟動索引，儲存後毫秒更新——讓 AI Agent 永遠持有最新的代碼地圖。

7.1 初始化你的第一個 CodeGraph 專案

完成 MCP 配置之後，下一步是為你的具體專案建立知識圖譜資料庫。 進入專案根目錄，執行互動式初始化：

bash 
# 進入你的專案根目錄
cd /path/to/your-project

# 執行互動式初始化（-i = interactive）
codegraph init -i

-i 旗標（interactive）會引導 CodeGraph 自動偵測語言與框架， 並即時顯示索引進度：

初始化輸出範例

  Found 312 TypeScript files
  Found 45 JavaScript files
  Building knowledge graph...

✓ Indexed 1,247 nodes (functions, classes, interfaces)
✓ Resolved 3,891 edges (calls, imports, extends)
✓ FTS5 index built

生成的檔案結構

初始化完成後，專案根目錄會出現一個新的隱藏目錄：

目錄結構 
your-project/
├── .codegraph/
│   └── codegraph.db    # 知識圖譜 SQLite 資料庫
├── src/
│   └── ...
└── package.json

.codegraph/codegraph.db 是從原始碼自動重建的衍生產物， 建議加入 .gitignore，不應提交到版本控制：

.gitignore 
# .gitignore 加入此行
.codegraph/

大型專案的記憶體配置（OOM 防護）

超過 50,000 行程式碼的大型專案，Node.js 預設的 1.5 GB 記憶體上限 可能在 Tree-sitter 全量解析時觸發 OOM（OutOfMemory）崩潰。 首次初始化時建議配置環境變數：

大型專案建議配置 
# 大型專案（> 50,000 行程式碼）建議配置
NODE_OPTIONS="--max-old-space-size=4096" codegraph init -i

# Windows PowerShell 對應語法
$env:NODE_OPTIONS="--max-old-space-size=4096"; codegraph init -i

Windows PowerShell 用戶請將 NODE_OPTIONS="..." 替換為 $env:NODE_OPTIONS="--max-old-space-size=4096"，在同一行前執行。

⚠️
僅首次全量索引需要此配置

全量索引完成後，後續的增量同步記憶體消耗極低， 無需保留 NODE_OPTIONS 環境變數。

7.2 增量自動同步的工作原理

CodeGraph 啟動後會在背景維持一個 OS 檔案系統監聽器（File System Watcher）， 持續監控專案目錄內所有原始碼的異動。 每當你儲存檔案（Cmd+S 或 Ctrl+S）， 監聽器並不會立即同步，而是啟動一個 2000 ms 的 Debounce 計時器。

自動同步觸發條件 
# 自動同步的觸發條件：
# 1. 檔案儲存（Cmd+S / Ctrl+S）後 2000ms debounce
# 2. 新增或刪除原始碼檔案
# 3. 重命名目錄

# Debounce 設計目的：
# 在快速連續儲存多個相關檔案時（例如同時改動介面和實作），
# 合併成一次增量更新，避免重複解析同一符號。

計時器到期後，CodeGraph 僅重新解析已變更的檔案，更新節點與邊的差異， 而非全量重建整個圖。對一個 1,000 個節點的中型專案而言， 單次增量同步通常在 50–200 ms 內完成。

ℹ️
哪些檔案會被監聽？

File Watcher 自動排除 node_modules/、.git/、dist/、build/ 等常見產物目錄，以及隱藏資料夾（. 開頭）。只有原始碼檔案的變更才會觸發增量解析，避免 IDE 自動生成的暫存檔造成不必要的重建。

1.x 的三層防線：確保 Agent 不會拿到過期答案

1.x 版在檔案監聽之外，又加了兩層保護，避免「剛存檔、還沒同步完」的空窗期給出錯誤的答案：

層級做什麼
1. 檔案監聽＋防抖同步 用 OS 原生事件（FSEvents／inotify／ReadDirectoryChangesW）捕捉建立、修改、刪除，防抖時間預設 2000ms，到期後只同步有變動的檔案。
2. 逐檔過期警告橫幅 防抖等待期間，如果 MCP 工具的回應會引用到「還沒同步」的檔案，回應最前面會加上 ⚠️ 警告，點名該檔案並要求 Agent 直接去 Read 它。
3. 連線時補同步 MCP 伺服器（重新）連線時，在回答第一個查詢之前，先用 (size, mtime) 加內容雜湊比對工作目錄，補上沒有伺服器在跑時所做的修改。

隨時可以用 codegraph status 檢查：如果有尚未同步的檔案，輸出會多一個 ### Pending sync: 區塊，列出檔名與修改後經過的時間。

ℹ️
什麼時候才需要手動 codegraph sync？

只有三種情況：監聽被停用（沙箱環境、或設定 CODEGRAPH_NO_DAEMON=1）、 在 Agent 以外的腳本裡直接查索引、或 git pull 拉入大量變更後想先同步。 在 WSL2 的 /mnt 這類很慢的檔案系統上，也可以用 codegraph serve --mcp --no-watch 關掉監聽。

手動同步指令

git pull 拉入大量變更後，或懷疑資料庫狀態不一致時， 可手動觸發全量同步：

bash 
# 手動觸發全量同步
codegraph sync

# 查看目前索引狀態與統計
codegraph status
ℹ️
MCP 伺服器需要先啟動

自動同步功能需要 codegraph serve --mcp 在背景執行。 使用 Claude Code 或 Cursor 時，MCP 伺服器通常由 IDE 自動啟動， 無需手動管理。

7.3 Monorepo 多套件初始化策略

如果你的專案是 Monorepo 架構（多個子套件共用一個 Git 儲存庫）， 建議針對每個功能邊界明確的 package 分別執行 codegraph init -i，各自生成獨立的 codegraph.db 索引。

分開索引的好處是：Agent 查詢 api 套件時不會被 frontend 的前端元件干擾，各套件的影響力分析也更精準。

7.4 TypeScript API 程式化控制

除了 CLI 和 MCP 工具，CodeGraph 提供 TypeScript/JavaScript API， 可在 CI/CD 腳本或自製分析工具中程式化地操作知識圖譜：

src/scripts/analyze.ts 
import CodeGraph from '@colbymchenry/codegraph';

// 初始化（自動讀取已有的 codegraph.db）
const cg = await CodeGraph.init('/path/to/project');

// 全量索引（首次使用，或資料庫遺失時）
await cg.indexAll();

// 快速符號搜尋
const results = cg.searchNodes('UserService');

// 取得直接調用者
const callers = cg.getCallers(results[0].node.id);

// 取得直接被調用者
const callees = cg.getCallees(results[0].node.id);

這個 API 尤其適合整合到 CI Pipeline——讓每次 PR 自動查詢受影響的模組範圍， 無需啟動完整的 MCP 服務堆疊。 下一章將示範如何結合影響力分析與 Vitest 實現精準的增量測試。

💡
與 postinstall 整合

在 package.json 的 postinstall 腳本中加入 codegraph sync，確保每次 npm install（包含 CI 環境） 都能自動更新知識圖譜，與代碼庫保持同步。

本章核心指令速查

首次初始化：codegraph init -i ｜ 查看狀態：codegraph status ｜ 手動同步：codegraph sync ｜ 清除索引：codegraph uninit。大型專案（>50k 行）首次初始化前記得設置 NODE_OPTIONS="--max-old-space-size=4096"。
