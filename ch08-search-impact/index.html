搜尋與影響力分析實踐

掌握 10 個 MCP 工具的智慧分流，讓 Agent 用最少的工具調用次數完成最複雜的代碼探索。

8.1 10 個 MCP 工具的智慧分流

CodeGraph 向 MCP 客戶端暴露 10 個工具，設計上分為兩類： 重型工具在任務開始時一次給足完整結構； 輕型工具在精準修改階段提供外科手術式的點狀查詢。 請參考以下決策樹，針對不同開發場景選擇對應的查詢工具：

💡
全部設為自動允許

這 10 個工具全部是唯讀查詢，不會修改任何原始碼或檔案。 建議在 .claude/settings.json 配置完整的自動允許清單， 省去每次調用時手動點擊確認的摩擦（詳見 8.5 節）。

8.2 調用鏈追蹤實戰：codegraph_trace

codegraph_trace 是整個工具集中最高頻使用的「核心神技」。 它能回答「從 Controller 到 SQL 執行，中間經過了哪些方法？」這類問題， 並且能穿透 EventEmitter、回呼函數、React 重渲染等動態分發邊界—— 這是 grep 無法做到的。

bash 
# 查詢 BigScreenController 到 selectOverview 的完整調用路徑
codegraph trace BigScreenController selectOverview

調用結果顯示每一跳的函數體，並明確標注動態分發邊：

trace 輸出範例 
Trace: BigScreenController → selectOverview
══════════════════════════════════════════════

① BigScreenController.getOverview()  [src/controller/BigScreenController.ts:42]
  └─ calls ②

② BigScreenService.buildOverviewData()  [src/service/BigScreenService.ts:118]
  └─ calls ③ (dynamic dispatch via EventEmitter, provenance: heuristic)

③ BigScreenMapper.selectOverview()  [src/mapper/BigScreenMapper.ts:67]
  └─ [TERMINUS: SQL query execution]

Total hops: 3  |  Dynamic dispatch: 1  |  Time: 0.8ms

注意第 ②→③ 跳的 provenance: heuristic 標注——這表示 CodeGraph 的 Synthesizer 模組偵測到了 EventEmitter 訂閱模式， 在圖中補充了啟發式推斷的合成邊，使調用鏈保持完整 （見第 3 章 Synthesizers 說明）。

ℹ️
通常一次 Trace 就夠了

在實際測試中，使用 codegraph_trace 的 Agent 完成調用鏈探索， 平均只需 1 次工具調用； 沒有 Trace 的 Agent 平均需要 17 次 grep/read。

8.3 影響力分析實戰：codegraph_impact

在修改核心服務（如 UserService）之前， 影響力分析可以告訴你這個改動會波及哪些上游調用者和測試檔案：

bash 
# 評估修改 UserService 會波及哪些下游模組
codegraph impact UserService

# 搭配 --depth 限制搜尋深度（避免影響半徑過大）
codegraph impact UserService --depth 3
impact 輸出範例 
Impact Analysis: UserService
══════════════════════════════════════════════

Direct callers (depth 1):
  - AuthController.login()           [src/controller/AuthController.ts:28]
  - AuthController.register()        [src/controller/AuthController.ts:55]
  - ProfileController.updateUser()   [src/controller/ProfileController.ts:91]

Indirect callers (depth 2):
  - SessionMiddleware.validate()     [src/middleware/SessionMiddleware.ts:34]

  - auth.controller.spec.ts
  - user.service.spec.ts

Total impact radius: 4 callers + 3 test files

輸出清楚列出直接調用者、間接調用者，以及有風險的測試檔案。 Agent 可以根據這份清單精準決定需要閱讀哪些程式碼、 以及哪些測試需要在修改後重新驗證。

8.4 結合 Vitest 的增量測試工作流

影響力分析最強大的應用之一是與測試框架整合，實現增量測試： 只跑與本次 git 變更有直接關聯的測試，而非每次都執行完整測試套件。 在大型專案中，這可以將 CI 時間從數分鐘縮短到數十秒。

增量測試漏斗流程圖 (Incremental Test Pipeline)
1. Git Diff 檢測變更
找出所有修改過的原始碼檔案 (ex: UserService.ts)
▼
2. CodeGraph 影響力反推
codegraph affected：反向追蹤所有受波及的模組與測試檔
▼
3. 執行測試 (Vitest)
xargs vitest run：精準只跑 3 個相關測試，跳過其餘 1000 個
bash（增量測試 Pipeline） 
# 結合 codegraph affected 只跑有風險的測試
git diff --name-only HEAD | codegraph affected --stdin --quiet | xargs vitest run

這條指令的三個步驟：

  1. git diff --name-only HEAD：取得與上一個 commit 相比發生異動的檔案清單。
  2. codegraph affected --stdin --quiet：根據異動檔案，反向追蹤所有受影響的測試檔案。
  3. xargs vitest run：只執行這些有風險的測試，跳過其餘測試。

建議封裝為 package.json script，方便 CI 和本地開發者統一呼叫：

package.json 
{
  "scripts": {
    "test:affected": "git diff --name-only HEAD | codegraph affected --stdin --quiet | xargs vitest run",
    "test": "vitest run"
  }
}

8.5 允許清單：消除 MCP 工具確認摩擦

預設情況下，Claude Code 每次呼叫 MCP 工具都需要手動點擊確認。 由於 CodeGraph 的 10 個工具全為唯讀，建議在 .claude/settings.json 加入完整的允許清單：

.claude/settings.json 
{
  "permissions": {
    "allow": [
      "mcp__codegraph__codegraph_search",
      "mcp__codegraph__codegraph_callers",
      "mcp__codegraph__codegraph_callees",
      "mcp__codegraph__codegraph_impact",
      "mcp__codegraph__codegraph_node",
      "mcp__codegraph__codegraph_files",
      "mcp__codegraph__codegraph_status",
      "mcp__codegraph__codegraph_trace",
      "mcp__codegraph__codegraph_explore",
      "mcp__codegraph__codegraph_context"
    ]
  }
}
⚠️
僅適用於唯讀工具

這份清單只涵蓋 CodeGraph 的查詢工具。 會修改檔案的工具（Edit、Write 等） 不應加入自動允許，應保留人工確認的安全閥。

8.6 輕型工具速查

在精準定位符號、微調程式碼的階段，以下輕型工具是你最常用的工具箱。 查詢延遲通常在 1 ms 以內（SQLite FTS5 + 索引查詢）， 比傳統 grep 全文掃描快 100x 以上：

bash（輕型工具速查） 
# 快速定位符號所在的檔案與行數
codegraph search UserService

# 查詢直接調用者（上游）
codegraph callers UserService.authenticate

# 查詢直接被調用者（下游）
codegraph callees UserService.authenticate

# 取得單一符號的詳細資訊與源碼
codegraph node UserService.authenticate

# 比 OS 更快的結構化檔案樹導航
codegraph files "src/service/**"

# 確認目前索引狀態
codegraph status
