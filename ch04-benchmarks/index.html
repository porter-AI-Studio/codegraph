效能基準測試與省代幣分析

用數據證實本地圖譜能為開發費用「減重」

一、 效能測試方法論

為了驗證 CodeGraph 的真實成效，作者採用了極為嚴謹的測試模型。測試環境採用 claude -p (以無介面 Headless 模式運行 Claude Opus 4.8)，對多個著名開源專案提出高度複雜的架構探索問題：

  • WITH 组 (啟用 CodeGraph)：啟用 CodeGraph 的 MCP 伺服器，同時 Agent 仍可自由選擇調用原生的 Read/Grep/Bash。
  • WITHOUT 组 (對照組)：停用 CodeGraph 的 MCP 設定，Agent 僅能依靠傳統的 find/grep/Read 進行代碼檢索。

每組均運行 4 次並取其中位數，以得出最貼近日常開發的統計學表現。

四、 邊際效益：項目規模與 Token 節省的相關性

從基準測試數據中可以發現一個顯著的工程規律：專案代碼規模越龐大，CodeGraph 帶來的 Token 節省與費用降幅就越驚人。

在小型專案（如 Gin，約 110 個檔案）中，由於程式結構簡單，Agent 僅靠原生 Grep 也能在較短時間內摸清脈絡，此時 Token 節省約為 23%。然而，一旦專案規模上升到萬個檔案的超大型代碼庫（如 VS Code），傳統 Agent 為了「尋路」而產生的上下文堆疊呈指數級膨脹，此時 CodeGraph 本地圖譜就能發揮極強的防迷路能力，將 Token 消耗直接降低 64%。

五、 為什麼 CodeGraph 能帶來如此高的降幅？

  1. 拒絕大範圍掃查：啟用 CodeGraph 後，Agent 面對架構問題時通常只需要呼叫 1~2 次 codegraph_explore 或 codegraph_trace 工具，即可透過本地索引精準解析出跨檔案的調用邏輯，完全省去了反覆 Grep 與遍歷檔案的上下文堆疊。
  2. 精確控制上下文大小：CodeGraph 會自動壓縮過濾無關的函數內部代碼，僅向模型返回符號簽章（Signature）與必要的關聯邊資訊。模型不需要被動吞下大片無用的重複程式碼。
  3. 預防 Explore Agent 溢出：在沒有 CodeGraph 的情況下，Agent 時常會派生出大量的 Subagent 去並行 Grep，每個子代理都會攜帶大份上下文，這會導致費用隨運行時間呈指數型（Exponential）增長。
