SQLite 技術解析

輕量嵌入式關係引擎與本地全文檢索優勢

一、 為什麼本地 Code Graph 選擇 SQLite？

許多面向 AI Agent 的工具，其底層索引往往需要在幾毫秒內響應多次查詢。相較於客戶端-伺服器端資料庫（如 PostgreSQL），SQLite 具備以下三大核心優勢：

  1. 零配置部署 (Zero Configuration)：資料庫完全由單一的本地檔案（如 codegraph.db）表示，無須在主機上安裝、執行或授權任何資料庫伺服器行程。
  2. 嵌入式讀取 (In-Process Call)：無須通過 TCP/IP 網絡插座 (Socket) 進行通訊，所有 SQL 呼叫均在當前處理的記憶體邊界內完成，免除了昂貴的網絡來回時間。
  3. ACID 安全性：採用原子性、一致性、隔離性、持久性設計，即使在 Agent 寫入代碼到一半、強制中斷或斷電時，也能保證圖資料庫檔案不毀損。

二、 併發的核心：WAL (Write-Ahead Logging) 模式

SQLite 預設採用 Rollback Journal 模式，寫入時會鎖定整張表，讀取行程必須等待。這對需要即時同步的 AI Agent 非常不利。CodeGraph 預設啟用 WAL 併發模式：

  • 當有新的代碼索引要寫入時，變更會先寫入一個獨立的 -wal 日誌暫存檔中。
  • 此時，讀取 SQLite 的 AI Agent 行程可以直接跳過暫存，直接讀取原始 .db 庫，並動態合併 wal 的紀錄。
  • 優勢：實現了讀寫行程互不阻塞，支持一邊進行 Tree-sitter 背景增量索引，一邊給 Agent 提供圖譜查詢。

三、 全文索引：FTS5 (Full-Text Search) 虛擬表

為了能夠在一瞬間從數萬行代碼中找到符號名稱或 docstring，SQLite 內建了 FTS5 全文檢索引擎虛擬表。

FTS5 採用倒排索引（Inverted Index）記錄單字在哪些行、哪些欄位中出現。以下為其實現 Schema 與模糊查詢的實戰 SQL 寫法：

// 1. 建立基於 FTS5 的虛擬表，將我們關心的欄位註冊進去
CREATE VIRTUAL TABLE nodes_fts USING fts5(
    name,
    signature,
    docstring,
    content='nodes' -- 指向原始實體表
);

// 2. 當 nodes 插入新符號時，更新 FTS5 倒排索引
INSERT INTO nodes_fts(rowid, name, signature, docstring) 
VALUES (last_insert_rowid(), 'validateToken', 'function validateToken(token: string)', 'Validate JWT');

// 3. AI 呼叫 MCP search 工具時，進行超高速匹配
SELECT rowid, name FROM nodes_fts WHERE nodes_fts MATCH 'validate AND JWT';

四、 CodeGraph 的資料表 Schema

CodeGraph 在本地端 SQLite 建立的資料結構精確且輕量：

CREATE TABLE nodes (
    id TEXT PRIMARY KEY,          -- 符號路徑 (如 func:src/auth.ts:validateToken:45)
    kind TEXT NOT NULL,           -- class, function, method 等
    name TEXT NOT NULL,           -- 符號短名稱
    qualified_name TEXT,          -- 全稱 (包含命名空間)
    file_path TEXT NOT NULL,      -- 所屬檔案路徑
    start_line INTEGER,           -- 起始行號
    end_line INTEGER,             -- 結束行號
    language TEXT,                -- 代碼語言
    signature TEXT,               -- 宣告簽名 (如 function validateToken(t: string))
    docstring TEXT,               -- 註釋文檔
    code_snippet TEXT             -- 原始碼片段
);

CREATE TABLE edges (
    source_id TEXT,               -- 關係起點節點 ID
    target_id TEXT,               -- 關係終點節點 ID
    kind TEXT NOT NULL,           -- calls, imports, extends 等
    resolved INTEGER DEFAULT 0,   -- 是否已成功尋找到定義
    line_number INTEGER           -- 在第幾行發生調用
);
