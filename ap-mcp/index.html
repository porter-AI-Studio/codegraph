MCP 協定解析

AI Agent 時代的「USB-C」通用串接標準

一、 什麼是 Model Context Protocol (MCP)？

MCP 是一項由 Anthropic 於 2024 年 11 月推出並開源的開放標準。它旨在解決 AI 代理生態中的「N x M」集成黑洞問題：

在 MCP 出現之前，如果要將 N 個 AI 模型與 M 個外部系統（資料庫、文件系統、外部 API）連線，開發者必須針對每一對模型與系統編寫特殊的 API 連線程式。而 MCP 提供了一個統一且標準化的接口規格，讓任何 AI Host (例如 Claude Code) 都能透過統一的通訊語法，與任何符合 MCP 標準的伺服器直接連線互動。

二、 核心元件與架構分層

MCP 協定包含三個關鍵組成部分：

  • MCP 主機 (Host)：執行 AI 代理的核心軟體或 IDE（如 Cursor, Claude Code, Antigravity IDE）。主機負責控制整體開發邏輯，並決定何時向 LLM 提案調用外部工具。
  • MCP 用戶端 (Client)：內嵌在 MCP 主機內，負責將 LLM 的結構化要求轉換為 MCP 規範的 JSON-RPC 協議訊息，並將伺服器返回的結果格式化回傳給 LLM。
  • MCP 伺服器 (Server)：專屬的本地或遠端程序（如 CodeGraph 運作的 serve --mcp 伺服器）。它向 Client 曝露專屬的 Tools、Resources 及 Prompts 接口。

三、 傳輸層協議比較

MCP 定義了兩種主要的底層雙向通訊通道：

特性項目 標準輸入輸出 (stdio) 伺服器推送事件 (SSE)
適用範圍 本地程序與本機資源 遠端微服務與雲端資源
通訊原理 OS 管道 (Standard Input/Output) HTTP SSE 串流 + POST 請求
優點 零網絡延遲、極其安全（資料不出本機） 支援跨主機聯網，適合雲端大範圍運算
缺點 無法跨主機遠端調用 需要配置網絡安全與 TLS 加密

四、 JSON-RPC 2.0 訊息實戰

MCP 用戶端與伺服器之間採用標準的 JSON-RPC 2.0 標準傳遞請求與響應：

1. 索取可用工具清單 (Client ➔ Server)

{
  "jsonrpc": "2.0",
  "method": "tools/list",
  "id": 1
}

2. 返回工具清單 (Server ➔ Client)

{
  "jsonrpc": "2.0",
  "result": {
    "tools": [
      {
        "name": "codegraph_search",
        "description": "Fast symbol search in local SQLite database",
        "inputSchema": {
          "type": "object",
          "properties": {
            "query": { "type": "string" }
          },
          "required": ["query"]
        }
      }
    ]
  },
  "id": 1
}

五、 MCP 的安全考量

由於 MCP 伺服器具有存取本地代碼甚至執行本地 Shell 命令的巨大權限，在開發與整合時必須遵循以下安全防護原則：

  • 資料隱私安全：主機與伺服器進行數據交換前，必須取得使用者的授權。CodeGraph 設計為 100% 本地 SQLite 資料庫，保證代碼內容不透過 MCP 上傳至任何外部雲端。
  • XSS 與注入式防護：AI 代理輸出的內容有時會混合不受信任的源碼片段，MCP 用戶端在向使用者展示結果時，必須先對原始 HTML 字元進行轉義過濾。
  • 供應鏈安全驗證：開發者切勿安裝來自不明來源的第三方 MCP Server，因為惡意 Server 可以輕易在 callTool 時透過 Node.js 執行本地破壞指令。
