Neo4j 技術解析

原生圖資料庫的基石與關聯資料處理

一、 圖資料庫與 Labeled-Property Graph

與關係型資料庫（RDBMS）將資料儲存在表格中不同，圖資料庫將實體（Nodes）與關聯（Edges）作為一等公民儲存。目前最受業界歡迎的圖模型為 帶標籤的屬性圖模型（Labeled-Property Graph, LPG）：

  • 節點 (Nodes)：代表實體物件。節點可以附帶多個標籤 (Labels) 以分組，並擁有屬性鍵值對（如 {name: "UserService", language: "TypeScript"}）。
  • 關係 (Relationships)：連結兩個節點。關係必須具有名稱與方向（如 [:CALLS]、[:INHERITS]），關係上同樣可儲存屬性（如 {line: 120}）。
  • 原生圖儲存 (Native Graph Storage)：Neo4j 擁有專門優化的底層硬碟儲存引擎，免除關係型資料庫在執行 JOIN 時的昂貴成本，能實現超高速的免索引鄰接 (Index-Free Adjacency) 圖遍歷。

二、 Cypher 查詢語言實戰

Cypher 是 Neo4j 的官方聲明式圖查詢語言，使用直觀的括號代表節點，箭頭 -[]-> 代表關聯：

1. 節點與邊的創建 (Create)

CREATE (u:UserService {name: "UserService", file: "user.ts"})
CREATE (d:Database {name: "PostgreSQL"})
CREATE (u)-[r:CONNECTS {poolSize: 10}]->(d)

2. 複雜調用鏈遍歷 (Query)

// 查詢所有呼叫過 "AuthService" 類別方法的所有方法鏈
MATCH path = (a:Method)-[:CALLS*1..5]->(b:Method {class: "AuthService"})
RETURN path
LIMIT 10

三、 Neo4j 系統架構

在生產部署中，Neo4j 主要支援兩種架構模型：

1. 單機架構 (Standalone)

將資料庫單節點部署，開箱即用，適用於測試開發。缺點是面臨單點故障 (Single Point of Failure) 的風險。

2. 因果叢集架構 (Causal Clustering)

適合大規模企業級高可用部署。叢集由兩部分組成：

  • Core Servers (核心伺服器)：通常有 3 個以上的奇數個節點。通過 Raft 協議保證一致性，負責所有寫入與讀取。
  • Replica Servers (唯讀副本)：可以橫向無限擴充。透過非同步複製 Core 的數據，專門分流讀取流量，大幅提高查詢吞吐量。

四、 橫向效益對比案例

根據真實企業的遷移指標，圖資料庫帶來了極大的效率提升：

  • eBay 的物流路徑搜尋：將原本 MySQL 的解法替換為 Neo4j 後，查詢代碼行數減少了 10~100 倍，遍歷關係的效能快了 1000 倍。
  • Adobe 的元數據儲存：將 Cassandra 改用 Neo4j 後，由於去除了大量冗餘的關聯鍵，資料大小從 50TB 驟降至 40GB。
