CodeGraph 核心特點與優勢

解析 CodeGraph 實現極致本地代碼 RAG 的技術支柱

一、 儲存架構：SQLite + FTS5，拒絕圖資料庫的繁瑣

與許多使用 Neo4j 等重型圖資料庫或雲端向量庫的 Code RAG 工具不同，CodeGraph 採取了極度精簡的本地架構：全圖資料皆儲存在一個本地 SQLite 檔案中。

CodeGraph 採用 SQLite WAL (Write-Ahead Logging) 模式，讀寫互不阻塞。以下是其核心的資料表設計：

  • nodes：儲存代碼符號實體。包含 id (以字串路徑為唯一值，例如 func:src/auth.ts:validateToken:45)、kind、name、file_path、signature 及原始碼片段 code_snippet。
  • edges：儲存符號之間的關係邊。包含 source_id、target_id、關係種類 kind 以及是否已被成功解析的 resolved 標記。
  • nodes_fts (FTS5 全文索引)：專門用於極速進行符號名稱與文檔字串模糊搜尋的虛擬表。

由於圖的規模限制在單一專案內（通常小於 10 萬個節點），SQLite 的索引結構在進行深度優先搜尋 (DFS) 或廣度優先搜尋 (BFS) 時，查詢耗時皆小於 1 毫秒，效能甚至優於許多企業級的圖資料庫。

二、 跨越靜態分析邊界：動態分發橋接 (Synthesizers)

傳統的靜態分析工具最害怕遇到「非硬編碼調用」，例如：運行時的事件監聽（EventEmitter）、回呼函數（Callback）或動態反射綁定。這往往會導致代碼調用鏈（Call Chain）斷裂。

CodeGraph 透過手寫的動態解析器（Synthesizers）解決了這個痛點。它能智能識別特定代碼模式，並在圖譜中手動加上一條標記為啟發式的合成邊（provenance: 'heuristic'）：

  • EventEmitter 橋接：當偵測到 emitter.emit('event_name') 與 emitter.on('event_name', handler) 時，自動建立 calls 邊。
  • 前端組件傳播：識別 React / Vue 的 JSX 宣告，穿透組件的 Props 傳遞與渲染邊界，將 render 與子組件連成一體。
  • ORM 關係穿透：對 Django 或 Prisma 的資料庫 Model 描述符進行語意關聯，使 Agent 能順利從資料庫操作查出對應的欄位模型。

三、 Web 框架感知路由 (Framework-aware Routes)

CodeGraph 內建了對 14 種主流 Web 框架路由宣告的語意抽取模組。這使得它在處理 Web 專案時極具優勢。

當 Tree-sitter 掃描到路由設定檔時，會將路由路徑與請求方法（例如 POST /api/v1/auth/login）抽象為一個 kind: 'route' 的節點，並直接連結到負責處理該請求的後端 Controller 或 Handler 函式節點。

支援的框架清單：

  • Python: Django, Flask, FastAPI
  • Node.js / JS: Express, NestJS (含 GraphQL/WebSocket), React Router, SvelteKit
  • PHP / Ruby / Go: Laravel, Rails, Gin, Chi, Axum, Actix Web
  • .NET: ASP.NET Core (含屬性路由 [HttpGet] 等)

四、 原生檔案同步監聽 (Debounced Auto-Sync)

為了確保 Agent 獲取的資訊永遠是最新的，CodeGraph 實作了極低消耗的即時檔案同步監聽器。

它呼叫系統底層的原生監聽 API（macOS FSEvents、Linux inotify、Windows ReadDirectoryChangesW），當開發者編輯代碼並存檔（Cmd+S）時：

  1. 自動過濾掉無關檔案（如 node_modules、隱藏資料夾與編譯產物）。
  2. 採用 2000ms 的防抖 (Debounce) 機制。在開發者連續輸入代碼時不進行無謂的頻繁重整，直到代碼靜止 2 秒後，才對受影響的檔案執行增量語法樹解析（Incremental Reparse）。
  3. 毫秒內將最新的節點關係更新寫入 SQLite，保證 AI Agent 下一次呼叫 MCP 工具時，永遠取得真實的程式狀態。
